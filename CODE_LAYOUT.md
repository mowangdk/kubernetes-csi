# Code Layout

This repository has a **dual-layer** layout that separates hand-maintained code
from code that is auto-generated by the sync tooling. The goal is to make it
obvious, for any file, whether it is a **source of truth** you may edit or a
**generated artifact** you must not.

## The two layers

### 1. `tools/` — hand-maintained source of truth

Everything under `tools/` is written and maintained by developers. This is the
only place you edit tool code.

```
tools/
├── cmd/csi-sidecars/
│   ├── main.go                     # AIO unified entry point
│   ├── main_test.go                # tests for parseControllers + config->global mapping
│   └── config/
│       ├── flags.go                # AIO + snapshotter flag registration
│       └── flags_test.go
├── pkg/attacher/cmd/csi-attacher/  # forked attacher entrypoint (flag-init strategy)
│   ├── main.go
│   └── config/
│       ├── flags.go                # attacher flag registration
│       └── flags_test.go
├── scripts/
│   ├── sync.sh                     # sync script (formerly hack/do_sync.sh)
│   ├── cleanup.sh                  # cleanup script (formerly hack/do_cleanup.sh)
│   ├── retry-go-dependencies.sh     # bounded Go dependency transport retries
│   ├── retry_go_dependencies_test.py # retry and checksum-safety regression tests
│   ├── verify_artifacts.py         # README CLI and image packaging smoke checks
│   ├── verify_artifacts_test.py    # verifier regression tests
│   └── sidecars.conf               # list of sidecars to sync (<sidecar>,<branch>)
├── csi-release-tools-hashes.txt
├── sync.log                        # reference log of a successful sync (generated, tracked)
└── README.md
```

### 2. Assembly area — generated by sync, not committed

`tools/scripts/sync.sh` clones the upstream `kubernetes-csi/external-*`
repositories, rewrites their import paths, strips their `main()`/flag
boilerplate, and assembles everything into the repository root. The result is
build output and stays uncommitted (`.gitignore` excludes it); a fresh checkout
runs sync once, then builds with a plain `go build`. Re-running sync
regenerates it (for example after an upstream revision bump):

```
cmd/csi-sidecars/            # assembly dir for the merged AIO binary
├── main.go                  # -> symlink to tools/cmd/csi-sidecars/main.go
├── config/flags.go          # -> symlink to tools/cmd/csi-sidecars/config/flags.go
├── attacher_main.go         # GENERATED from external-attacher
├── provisioner_*.go         # GENERATED from external-provisioner
├── resizer_main.go          # GENERATED from external-resizer
└── snapshotter_main.go      # GENERATED from external-snapshotter
cmd/snapshot-controller/         # GENERATED standalone binary
cmd/snapshot-conversion-webhook/ # GENERATED standalone binary
pkg/                         # GENERATED upstream code (contains .GENERATED marker)
│                            #   pkg/attacher/cmd/csi-attacher/main.go is a symlink
│                            #   to tools/pkg/attacher/cmd/csi-attacher/main.go
staging/                     # GENERATED csi-lib-utils checkout
tmp/                         # temporary build intermediates
go.mod / go.work             # GENERATED by sync
```

Two files inside the generated `cmd/csi-sidecars/` are **symlinks** back into
`tools/` (the AIO `main.go` and `config/flags.go`), so the assembled binary
builds against the hand-maintained source. The forked attacher `main.go` is
likewise a symlink from `pkg/attacher/cmd/csi-attacher/main.go` into `tools/`.

## How to tell them apart

- Under `tools/` → hand-maintained, edit freely.
- `pkg/.GENERATED` marker file → the directory is auto-generated.
- A `// Code generated by tools/scripts/sync.sh from external-<sidecar>; DO NOT
  EDIT.` header just above the `package` clause → the file is auto-generated.
- Symlinks in the assembly area point at the real source under `tools/`.
- `.gitattributes` marks generated artifacts as `linguist-generated`.

## Workflow

```bash
# Regenerate the assembly area from upstream + hand-maintained tools/. Requires
# the locked Linux builder; generates go.mod/go.work and vendors dependencies.
./tools/scripts/sync.sh --update-dependencies 1.MINOR.PATCH

# Build directly from a populated tree (no sync needed).
make build

# Remove all generated artifacts (leaves tools/ untouched).
./tools/scripts/cleanup.sh
```

Makefile shortcuts: `make sync KUBERNETES=1.MINOR.PATCH` runs
`tools/scripts/sync.sh --update-dependencies`, and `make clean` extends the
release-tools `clean` (removes `bin/`) with `tools/scripts/cleanup.sh`.

To change which sidecars are synced or from which branch, edit
`tools/scripts/sidecars.conf`.
